
# DigitalOcean Infrastructure and Docker Swarm Setup

## Overview

This document describes the cloud infrastructure configured for the ECE1779 Collaborative Task Management Platform.

The infrastructure was set up by Ishmam Ahmed as part of the Cloud Infrastructure and DevOps responsibilities.

The application uses two DigitalOcean Droplets connected through a private VPC, with Docker Swarm for multi-node container orchestration. PostgreSQL uses an attached DigitalOcean Block Storage volume for persistent data.

## 1. DigitalOcean Droplets

Two Ubuntu 24.04 LTS Droplets were provisioned in DigitalOcean's Toronto region (TOR1).

| Configuration | Manager | Worker |
|---|---|---|
| Hostname | ece1779-swarm-manager | ece1779-swarm-worker |
| Operating System | Ubuntu 24.04 LTS | Ubuntu 24.04 LTS |
| vCPU | 1 | 1 |
| RAM | 2 GB | 2 GB |
| Boot Disk | 50 GB | 50 GB |
| Docker Engine | 29.9.3 | 29.9.3 |
| Docker Compose | v5.7.0 | v5.7.0 |
| Swarm Role | Manager | Worker |

Both Droplets are connected to the same private DigitalOcean VPC.

The manager's private IP address is `10.118.0.2`.

SSH key-based authentication is used for server access.

## 2. Docker Installation

Docker Engine and Docker Compose were installed on both Droplets using Docker's official Ubuntu repository.

The following commands were used to verify the installations:

```bash
docker --version
docker compose version
systemctl is-active docker
```

Both servers reported Docker Engine version 29.9.3, Docker Compose version v5.7.0, and an active Docker service.

## 3. Docker Swarm Configuration

Docker Swarm was initialized on the manager using its private VPC address:

```bash
docker swarm init --advertise-addr 10.118.0.2 --data-path-addr 10.118.0.2
```

The worker joined the Swarm cluster using the worker join token generated by the manager.

The token is intentionally excluded from this documentation.

Cluster status was verified on the manager using:

```bash
docker node ls
```

Both nodes reported `Ready` status and `Active` availability.

The manager was identified as the Swarm Leader.

## 4. Multi-Node Container Replication Test

To verify container placement across the two Droplets, a temporary Nginx service was deployed:

```bash
docker service create \
  --name ece1779-test \
  --replicas 2 \
  --replicas-max-per-node 1 \
  nginx:alpine
```

The `--replicas 2` option requested two running containers.

The `--replicas-max-per-node 1` option restricted placement to one replica per node.

Service placement was checked using:

```bash
docker service ps ece1779-test
```

Observed results:

| Replica | Node | Status |
|---|---|---|
| ece1779-test.1 | ece1779-swarm-worker | Running |
| ece1779-test.2 | ece1779-swarm-manager | Running |

Both replicas successfully ran on separate Droplets.

The temporary service was removed afterward:

```bash
docker service rm ece1779-test
```

The service list was verified as empty using:

```bash
docker service ls
```

This test confirmed cross-node container scheduling and replica placement. Application-level load balancing and failover testing remain pending.

## 5. PostgreSQL Persistent Storage

A separate 10 GB DigitalOcean Block Storage volume was attached to the manager.

The volume uses the ext4 filesystem.

Mount point:

```text
/mnt/volume_tor1_1794236977286
```

A directory was created for PostgreSQL database files:

```text
/mnt/volume_tor1_1794236977286/postgres-data
```

The directory was created using:

```bash
mkdir -p /mnt/volume_tor1_1794236977286/postgres-data
```

Storage was verified using:

```bash
lsblk -f
df -h
findmnt -T /mnt/volume_tor1_1794236977286
```

## 6. Persistent Mount Configuration

DigitalOcean configured the volume through the systemd mount unit:

```text
mnt-volume_tor1_1794236977286.mount
```

The mount references the filesystem by UUID rather than a potentially changing device name.

Its configuration was inspected using:

```bash
systemctl cat mnt-volume_tor1_1794236977286.mount
```

Automatic mounting was verified using:

```bash
systemctl is-enabled mnt-volume_tor1_1794236977286.mount
```

The result was `enabled`.

Cameron subsequently rebooted the Droplets and confirmed that the persistent storage remained available afterward.

## 8. Architecture Limitations

The current infrastructure consists of one Docker Swarm manager and one worker.

Although the setup supports running application replicas on separate nodes, it does not provide full high availability.

The single manager and PostgreSQL instance are potential points of failure.

A larger production deployment could use additional manager nodes and database replication, but those components are outside the scope of this course project.
